# 解读 loss 数值：为什么裸 loss 需要一条基准线

当你看 capacity grid 时，每个格子都打印一个 `loss`。很容易把它当成一个绝对分数来读——"越低越好，0 就是完美"。这**基本**对，但单独一个裸 loss 数值是没有意义的。要把它变成一个你能信任的分数，每个任务你都需要两个参照点：

- 一条**地板（floor）**——任何模型可能达到的最好 loss（常常**不是** 0），以及
- 一条**天花板（ceiling）**——一个**什么都没学到**的模型的 loss（预测一个常数）。

一个 loss 只有**相对于这两个锚点**才意味着"好"或"坏"。这篇笔记为本仓库的两个任务推导出这两个锚点，展示 grid 里死掉的格子是如何**恰好**落在天花板上的，并给出一套实用的读数方法。

> 一句话总结：在同一个任务内，每个架构的 loss 都处在**相同量纲**下（相同数据 + 相同 loss 函数），所以它**确实**是一个有效的比较——比较的是*这一次训练的拟合*。但要对照下面的基准线来解读它——并且记住：低到"已解决"阈值以下时，那些差异是优化噪声，而不是架构高下。

---

## 每个任务的两个锚点

| 任务 | loss 函数 | **天花板** = 什么都没学到（预测一个常数）| **地板** = 可能的最好值 |
|---|---|---|---|
| 回归（`y = x₁²+x₂² + 0.1·noise`）| MSE | **3.93** = `var(y)`（预测均值）| **0.01** = 噪声方差（不可约）|
| 分类（`label = 1 当 x₁·x₂ > 0`）| BCE | **0.69** = `H(p)`，p≈0.52（预测基础概率）| **≈ 0**（标签是确定性的）|

这些不是空口而谈——它们是从真实数据（`load_task(task).make_data(1000, 42)`）算出来的，而且 **grid 里死掉的格子正好坐在天花板上**：

```
回归死格   → loss = 3.929   (var(y) = 3.9286)
分类死格   → loss = 0.692   (H(0.519) = 0.6924)
```

这个精确的吻合，正是一个网络*塌缩*的标志性信号：它不再是其输入的函数，只是输出一个常数。

---

## 为什么天花板是这个值

一个隐藏单元全部死亡的网络（dying-ReLU 塌缩）再也无法随输入移动它的输出——它能做的最好的事就是发出一个常数。训练随后会把这个常数推向任何使 loss 最小的值：

**回归 / MSE。** 使 `mean((y − c)²)` 最小的常数 `c` 是均值 `ȳ`，而由此产生的误差，按定义，就是 `y` 的方差：

```
min_c  E[(y − c)²]  =  Var(y)
```

对这个数据集 `x₁, x₂ ~ N(0,1)`，所以 `x²` 的均值为 1、方差为 2，得到 `Var(x₁²+x₂²) = 4`，再加上一点噪声 → `Var(y) ≈ 3.93`。这就是为什么**每一个**死掉的回归格子都停在 3.93：它们全都在预测均值。

**分类 / BCE。** 使二元交叉熵最小的常数概率 `q` 是基础概率 `p = P(y=1)`，由此产生的 loss 是二元熵 `H(p) = −p·ln p − (1−p)·ln(1−p)`。这里 `p ≈ 0.519`，所以 `H(p) ≈ 0.692`（非常接近 `ln 2 ≈ 0.693`，即完美 50/50 划分时的值）。一个处处预测 ~0.5 的死掉的分类器就落在那里。

> **助记：** 天花板就是"最好的*常数*预测器的 loss"。回归 → `var(y)`。平衡分类 → `ln 2 ≈ 0.69`。

---

## 为什么地板通常不是 0

对于**回归**，目标里带着 `0.1·noise`，即一个方差为 `0.1² = 0.01` 的不可约随机成分。没有任何模型——无论多大——能预测噪声，所以 **0.01 是硬地板**（这个数据集的"贝叶斯误差"）。最好的几个 grid 格子达到 ~0.02–0.05，也就是说它们已经在贴着噪声地板了；剩下的差距大多是它们*无法*学到的噪声，而不是"还有提升空间"。在这里追求一个低于 ~0.01 的回归 loss，就是在追逐噪声。

对于**分类**，标签是确定性的（`x₁·x₂ > 0`），所以地板 ≈ 0。唯一不可约的难点是沿着坐标轴的一条无限细的带（在 `x₁≈0` 或 `x₂≈0` 处），平滑的 sigmoid 无法把它做得绝对锐利——这是一个测度为零的集合。最好的几个格子达到 ~0.001–0.004，实际上就是完美。

---

## 把 loss 变成一个可解读的分数：归一化它

裸 loss 处在每个任务自己的量纲上；要让它变得人类可读，就把天花板除掉。

### 回归 → R²（"被解释的方差比例"）

```
R² = 1 − MSE / Var(y) = 1 − MSE / 3.93
```

| MSE（loss）| R² | 在 grid 里长什么样 |
|---|---|---|
| 3.93 | 0.00 | 平的——在预测均值（**死**）|
| ~2.0 | ~0.49 | 单条斜坡/楔形（宽 2、深 1 的封顶）|
| 0.52 | 0.87 | 折叠的、有棱角的碗（宽 2 + 深度）|
| 0.05 | 0.99 | 平滑的碗（宽 ≥ 3）|
| 0.02 | 0.99+ | 贴着噪声地板的平滑碗 |
| 0.01 | ~0.997 | **可达到的最大** R²（噪声地板）|

所以"loss 0.05"真正的含义是"解释了 99% 的方差"——作为一个*分数*，这远比那个光秃秃的数字好读。

### 分类 → 准确率（带一个注意事项）

直观的归一化分数是**准确率**，但请注意 **BCE ≠ 准确率**：BCE 还奖励*校准/置信度*，所以两个准确率相同的网络可以有不同的 BCE。这里大致的对照如下：

| BCE（loss）| 含义 |
|---|---|
| 0.69 | ~50% — 瞎猜（**死**）|
| ~0.48 | ~75–80% — 解决了一条对角线划分，漏掉了另一条 |
| < 0.05 | ~100% — 完整的 XOR 棋盘（**解决**）|

---

## 另一个方向：低于"已解决"之后，差异就是噪声

在已经解决的格子之间，你会看到诸如 0.001 vs 0.003 vs 0.05 这样的 loss。**不要过度解读这个排名。** 那些差距由初始化和优化的随机性主导，而不是因为某个架构"更好"。同一个架构换一个 seed 重跑，就能轻易把那个顺序重新洗牌。

因此，读 grid 的稳健方式是**分桶**，而不是按小数排序：

| 桶 | 回归（R²）| 分类（BCE）|
|---|---|---|
| **已解决** | R² ≳ 0.98（loss ≲ 0.08）| BCE ≲ 0.05 |
| **部分** | 0 < R² ≲ 0.9（斜坡 / 折叠）| 0.05 < BCE < 0.6 |
| **失败（死）** | R² ≈ 0（loss ≈ 3.93）| BCE ≈ 0.69 |

"已解决"桶里的一切都应当被视为平局。

---

## 读 grid 的操作步骤

1. **锚定：** loss 是否靠近天花板（3.93 / 0.69）？→ 这个格子什么都没学到；它是*死的*，而不仅仅是"差一点"。
2. **归一化：** 转成 R²（回归）或粗略准确率（分类），让这个数字读起来像个分数。
3. **地板检查（回归）：** 它是否靠近 0.01？→ 它已经做到了数据所允许的极限；剩下的残差是噪声，别再优化了。
4. **分桶：** 已解决 / 部分 / 失败。别在"已解决"内部给小数排名。
5. **和图对照：** "what the network learned" 与 "the truth" 两个面板可以印证那个数字——死格子是一片纯色，已解决的格子与 truth 吻合。

---

## loss *不会*告诉你的两件事

- **泛化。** 打印出来的 loss 是*训练* loss（在这个教学设置里没有留出测试集划分）。它在这里恰好能跟踪泛化，仅仅是因为这些网络严重欠参数化（≤111 个参数 vs 1000 个数据点）且目标是平滑的——所以它们*无法*死记硬背。在一个真实的模型上你必须留出测试集；一个低的训练 loss 可能纯粹是过拟合。
- **架构的能力。** 单个格子的 loss = 架构 **+** 这个 seed 的初始化 **+** 这一次运行的优化运气。同一个架构在一个 seed 上可以读出 3.93（死），在另一个 seed 上读出 0.05（解决）。要给一个架构的*能力*打分，要在多个 seed 上做聚合（成功率 / best-of-N）——这正是 seed sweep 所做的，也正是为什么它是回答"这个架构有没有能力？"而非"这一次运行成功了吗？"的正确工具。
